# Steam 플레이 버튼 연결 설계

## 조사 결과

- 설치된 Steam 0.8.0의 Manual.txt는 사용자 애드온을 `--addon`으로 선택하도록 안내한다.
- 참고 소스 options.c의 `loadIndices`는 기본 RMP를 읽고, setup.c는 기본 리소스 뒤에 음성 등 공식 애드온을 읽는다. 기본 RMP 추가만으로는 최종 번역 우선순위를 보장할 수 없다.
- uqm.c의 `getUserConfigOptions`에는 텍스트 메뉴·폰트·스케일 설정이 있지만 사용자 애드온 목록은 명령행 파서에서 구성된다.
- 참고 소스는 Steam 바이너리와 동일 빌드를 증명하는 자료는 아니다. 최종 검증은 설치된 Steam 게임의 플레이 버튼으로 실행해 수행했다.

소스: https://github.com/intgr/uqm-wasm/tree/daadbb540a8c46f09dcdb0080b4212fb33e6cb94/sc2/src

## 선택한 방식

Steam 사용자 설정 localconfig.vdf의 해당 App ID(2645580) LaunchOptions 값만 수정한다. 게임 실행 파일, 리소스 로딩 순서, 원본 자료, 게임 설정, 저장 파일은 변경하지 않는다.
기존 옵션 뒤에 검증된 한국어 실행 인자를 추가하고, 원래 값과 적용 값을 설치된 애드온의 steam-launch.json에 저장한다. 이 파일은 개인 PC의 복원 자료이므로 저장소나 배포물에 포함하지 않는다.

Steam은 실행 중 설정을 메모리에 보관하므로 변경 직전 두 번 프로세스 종료를 확인한다. 설정 읽기 이후 내용이 달라졌다면 쓰기를 중단한다. 완전한 다른 프로세스와의 동시 실행 잠금은 아니므로 등록·복원 중 Steam을 다시 켜지 않는다.

VDF를 전체 재직렬화하지 않고 대상 값의 범위만 수정한다. 최근 계정은 MostRecent, AutoLogin, 단일 계정 순서로 확인하며 여러 후보면 중단한다. 게임을 한 번 실행하지 않아 대상 설정이 없다면 수동 확인을 요청한다.

제거 시 현재 옵션이 적용 값과 같을 때만 원래 값을 복원한다. 다른 게임의 옵션·플레이 시간 등은 그대로 둔다. 사용자가 옵션을 수정했거나 계정이 달라지면 자동 제거를 중단한다. 설정 쓰기 전에 복원 자료를 저장하며, 중간에 종료되면 steam-restore로 복구할 수 있다.

## 검증

- 옵션 유무·따옴표·역슬래시·주석·다른 게임 설정 보존
- 연결 반복 및 버전 업데이트 후 기존 백업 유지
- 사용자 옵션 수정·계정 변경·실행 중 Steam·쓰기 실패 보호
- 실제 Steam 플레이 버튼으로 실행 후 한글 함선 정보와 불러오기 메뉴 표시 확인

모든 번역 분기나 Steam 계정 전환 시나리오를 실기 검수했다는 뜻은 아니다. Linux/Steam Deck의 자동 연결은 지원하지 않는다.
